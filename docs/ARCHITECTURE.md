# 架构与关键取舍

PatchTrail把“模型提出动作”与“程序执行及判定结果”分开。当前v0.3提供操作者网页／CLI源码导入、单Agent调查、人工确认和新副本容器验证；匿名访问保留明确标识的脚本演示。任务、提案和检查结果都有可核对的版本与记录。

## 模块

| 模块 | 职责 |
| --- | --- |
| api.py | 请求校验、操作端权限、公开demo边界和错误响应 |
| service.py | Agent循环、预算、检查基线、补丁确认、恢复与终态 |
| providers.py | DeepSeek真实传输与明确标识的脚本provider |
| storage.py | SQLite状态、事件、幂等请求、乐观版本和重启恢复 |
| tasks.py与fixtures | 版本化任务、可编辑文件白名单和固定检查命令 |
| projects.py | 导入清单校验、内容身份及不可变私有源码快照 |
| web_imports.py | 认证后的网页预览与确认、限额、过期和重复提交核对 |
| check_profiles.py | 生成和核对固定unittest／pytest命令，不接受任意命令 |
| workspace.py | 有界读取、路径检查、内容哈希、补丁digest和新副本 |
| sandbox.py | Docker/Podman受限执行、输出与时间边界、容器清理 |
| frontend/src | React与TypeScript界面、导入、令牌边界、运行状态和补丁审阅 |
| web | 已构建的同源静态资源，通过REST接口操作后端 |

## 一条当前工作流

操作者选择源码和不可修改测试，填写问题，上传预览后确认导入。系统保存不可变私有快照并在网页选中新任务，这一步不创建运行、执行源码或调用模型。真实模式需要独立确认费用，服务器才把任务源码、测试和工具结果发给配置的DeepSeek服务；操作令牌与模型Key分开，网页不接收模型Key。

模型可使用五个工具：读文件、字面搜索、运行固定检查、提出单文件补丁、提出最多三文件补丁包。模型给出的是文件替换内容，由程序生成diff并校验。先确认原始测试实际失败，再接受提案，停在待审状态；审批后在新副本中应用准确补丁并检查。测试和配置不允许作为可修改源码。

`.diff`和JSON报告可以导出。提出补丁后即可下载diff，因此下载不代表验证通过；系统不自动修改用户电脑上的原项目、合并PR或发布修复。

## 三项面试主线

**模型说完成不等于检查通过。** Agent只能保存提案，不能直接修改原仓库或把状态设为成功。确认之后重新建立验证工作区；测试文件不在可编辑集合中。基线必须是真正执行过用例的失败，避免把镜像缺失等基础设施错误错当成业务错误。

**确认绑定的是具体内容与现场。** 提案digest包含源码、旧新内容、diff和工作区指纹；确认还要匹配运行版本。现场漂移会被拒绝。确认和状态变化在SQLite事务中提交；同一确认的HTTP响应丢失后，重试不会重复触发验证。

**恢复需要重新核对状态。** diagnosing/verifying在进程重启后标为interrupted，awaiting_approval保留。恢复验证从固定源码和已确认提案重建，不依赖半完成的临时目录。模型请求结果未知时不自动再次请求，保留相关记录供操作者判断。

## 为什么先用这些边界

SQLite加单worker适合当前单操作者、单机容量与可解释性。并发竞争用数据库事务和版本检查处理，暂不引入分布式队列。自带源码已能通过网页或CLI登记为私有任务；固定unittest／pytest环境由管理员预先准备，任务中不自动安装依赖或拉取镜像。

导入限制为最多200个文件、总计2MiB、每文件128KiB，最多三个可修改Python源码文件。网页导入先鉴权再读正文；预览有数量、大小和24小时过期界限，相同内容重复确认复用原任务。它不是多用户账户系统，操作令牌持有者进入同一操作者私有区；更多依赖、多租户与更大资源容量仍需另行设计和验收。

脚本provider与DeepSeek使用同一套工具和状态机。前者验证运行规则，后者才提供模型效果数据。公开演示的内置答案可从开源代码看到，不能作为未知修复能力测试。

容器提供具体隔离与资源约束，不意味着任意代码绝对安全；有限测试通过也不意味着程序对所有输入正确。正式多租户服务、任意仓库执行、自动合并PR和通用修复准确率不在当前交付范围内。

v0.3核心检查为126项Python；最终前端34项Node、TypeScript与构建通过，部分检查有包装重叠。2026-10-29复查再次通过这些本地检查，12份web资源字节未变化，三个公开脚本任务重新经过实际OCI验证；这些检查没有新增模型调用。网页导入实际预览／确认与费用窗口取消见[网页导入交付](WEB_IMPORT_DELIVERY_2026-10-29.md)。

真实模型效果另看[自有源码验收](V0_2_DELIVERY_2026-10-28.md)：三个预登记小功能、五次尝试，两个任务完成；两份pytest摘要提案因回归被拒绝且未应用，首次运行器统计误判及授权重试也保留。不能把脚本、上传成功或运行器测试计为模型修复成绩。当前状态以[项目状态](../PROJECT_STATUS.md)为入口，原[v0.1契约](IMPLEMENTATION_CONTRACT.md)保留历史范围。
