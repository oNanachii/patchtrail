# Invitation BYOK API (v0.4)

The old operator Bearer token remains supported in its separate legacy namespace. A member never receives that token or reads legacy private data. All member endpoints below use `Authorization: Bearer <session_token>`; browser keeps token and supplied key in page memory only and clears them on logout/reload.

- `POST /api/session` `{invite_code, api_key}` → `{session_token, role:"member", member_id, expires_at, model}`. No model request. Fixed DeepSeek official endpoint, server-selected model. Session expiry defaults to one hour; login with the same invitation returns the same isolated member data. Key lives only in server memory. No cookies/localStorage.
- `GET /api/session` → `{role:"member"|"operator", member_id?, expires_at?, model}`; invalid/expired/revoked session is 401.
- `DELETE /api/session` → `{logged_out:true}`. Logout, expiry and invitation revocation forbid subsequent model requests; an already dispatched HTTP request can finish and may be billed. Run records remain. Resume requires a current session and explicitly binds the new session.
- Existing `/api/tasks`, `/api/projects`, `/api/imports/*`, `/api/runs*` use member-local storage when a member session is provided. Unknown Bearer tokens fail 401 rather than falling back to demo. Member requests cannot address legacy or another member's runs/previews/tasks (404). Anonymous scripted demo and old operator use remain supported.
- `POST /api/tasks/{task_id}/preflight` (no body) → `{preflight_id, task_id, source_hash, check_profile, status, eligible, check, expires_at}`. Executes only the fixed container check. Status: `ready` (complete failing baseline), `already_passed`, `environment_missing`, `timed_out`, `unconfirmed`. Never calls a model or creates a run. Preflight is private to its member/operator, expires after 15 minutes and binds exact source/check configuration.
- `POST /api/runs` adds optional `preflight_id`. Member live runs require this eligible preflight; operator compatibility direct-live runs perform the same baseline before their first model request. The page must show preflight result and get explicit real-call confirmation before creating a live run. Existing approval digest/version contract remains unchanged.
- `GET /api/runs/{id}/files.zip` returns actual approved replacement files at original relative paths, `PATCHTRAIL_APPLY.md` and `patchtrail-manifest.json`, only for a successfully verified run. Snapshot/proposal integrity is rechecked. Existing diff and report exports remain.

Global execution is one shared bounded worker queue across operator/demo/members, including preflight checks. Defaults: 6 active runs globally; 2 active runs/member; 20 lifetime runs/member; 5 committed project snapshots/member; 32 staged previews/member (existing 24h expiry and source byte limits). Errors use existing `{error:{code,message}}`; capacity is 429, missing/stale/unusable preflight is 409, expired authentication is 401. Single API process only.

Invitation management is local CLI `python -m patchtrail.members create --data-dir ... --output ...` and `revoke --data-dir ... --member-id ...`. Random invitation credentials are written only to a newly created 0600 file, never printed; the registry persists only their digest. No public registration, dependency installation, payment, arbitrary endpoint or remote Git.

## Operational boundaries

Invitation creation is capped at 32 identities; in-memory sessions at 64. Session keys are cleared on logout and by an expiry timer, and credentials are rechecked at every model-dispatch boundary. A request authorized for dispatch before logout/revocation can still finish and be billed. The fixed timeout bounds that in-flight request; the next request is forbidden. Provider JSON and nested tool-argument JSON are redacted before any event/checkpoint persistence if they echo the supplied key.

Revoking an invitation atomically cancels that member's outstanding records with `invitation_revoked`, preserving all history and releasing global active-run capacity. Already running container/model work may finish but cannot overwrite a cancelled result. Member queued runs found after a process restart are retained as failed (`session_required`); active runs use the existing interrupted recovery boundary and require explicit current-session resume. Legacy operator storage is never migrated or reset.

The archive rechecks successful verifier status, exact approval digest and all original snapshot/file hashes. It contains only the approved source replacements plus instructions/manifest, not the full private project or tests. Copying files into a changed local project still requires checking the manifest's original hashes.

Member authentication requires HTTPS for every `/api/session` operation and every authenticated member API request. The backend rejects an insecure login before consuming any body bytes. The only HTTP exception is explicit local development where both the destination hostname/IP and the actual client IP are loopback (`localhost` is allowed as the destination). Arbitrary `X-Forwarded-Proto` headers do not grant HTTPS: only the ASGI scheme from the trusted server/proxy layer is used. Test clients use an HTTPS base URL, not a production `testserver` exception. Health exposes `run_limits` from the configured execution budgets.
