# PatchTrail 实用化范围与完成标准

2026年10月28日确定。下一版做到单操作者可导入自己的受限Python项目，围绕失败测试提出可审查补丁，在新环境复验并导出结果。完成下列标准后停止首版扩展，转入本人讲解、关键修改和简历投递。

确定此范围时公网为v0.1，仅支持三个内置任务。现工程部分已实现并部署为v0.2.1，当前事实见[V0.2交付验收](V0_2_DELIVERY_2026-10-28.md)；下文保留范围与停止标准，本人讲解/关键修改仍待实际验收。v0.1原契约与运行记录继续保留原义。

## 交付范围

| 环节 | 本次做到的程度 |
| --- | --- |
| 导入自己的代码 | 提供本地CLI预览并导入目录，以manifest登记源码、只读测试、可修改文件与固定测试profile。形成不可变快照，原项目不改写。网页可选择已导入的私有项目与任务。 |
| 导入限制 | 首版每个项目最多200个允许文件、源码与测试合计2MiB、单文件128KiB。拒绝符号链接和越界路径；排除.git、.env、虚拟环境、数据库、模型权重和构建产物。规则只减少误带入，仍需操作者检查文件清单。 |
| 问题定义 | 操作者给出简短问题描述及失败测试路径。基线必须实际运行正数测试并出现可归因的失败；零测试、环境异常和测试通过的任务分别返回明确状态。 |
| 测试与依赖 | 支持固定unittest与pytest两种profile，允许选测试路径或用例，不允许输入shell。仅使用部署前准备且固定digest的标准库镜像或轻量Web测试镜像，运行中不安装依赖，不执行仓库Dockerfile。 |
| 模型与补丁 | 一个DeepSeek Agent，保留现有有界工具循环与预算。每份提案最多修改三个白名单源码文件，作为一个原子补丁包审阅；测试、配置与依赖锁文件不可改。 |
| 确认与验证 | 审批绑定源码快照、全包digest及运行版本。由原快照重建新副本，再应用准确补丁，实际容器检查决定结果。 |
| 交付结果 | 下载统一.diff、JSON报告及可读结果，包含基线与修复后测试、修改清单、来源、模型用量和停止原因。导出的补丁须能在独立副本应用并复验。 |
| 权限与部署 | 导入项目、源码、提案和真实运行只允许操作者访问；匿名8444继续只开放内置脚本演示。密钥不进入快照、容器或报告。 |

本次不做多租户、任意公网上传、任意Git URL、GitHub OAuth、自动建PR/提交/合并、通用终端、多Agent、运行时联网装依赖、RAG或向量库。导出补丁后由操作者自行决定如何进入原仓库。

## 完成标准

1. 操作者能够用一条明确的导入命令登记真实目录，预览文件与测试配置；导入完成后不再依赖原目录也能复现任务。
2. 白名单外、测试文件、旧版本与旧digest被拒；多文件提案全部应用或全部拒绝。匿名接口、列表、事件与报告均不能泄露私有项目。
3. 容器不可用、零测试、超时、输出截断、真实测试失败、未知模型响应与进程中断各有可核对的停止原因。重复请求不凭客户端错误新建另一任务，不承诺外部调用精确一次。
4. 预先登记来自至少两个真实Python仓库的三个缺陷或小变更任务，写明来源、原始提交/快照与验收测试。优先选择PatchTrail自身历史问题、文本分类工作台中的真实问题或小功能；新功能任务不得包装成历史bug。
5. 所有真实模型尝试保留，包括失败、耗时和用量；至少两个任务完成“基线失败—模型提案—确认—回归通过—导出补丁—独立副本复验”。这仅用于实用链路验收，不发布通用成功率。人工注入故障单独标记，不能补成真实缺陷样本。
6. 本人能沿一条运行解释模型/工具、状态与幂等、确认与隔离验证，并亲手修改一个关键条件、复现与核对结果。AI完成代码不替代这一步。

首版不在容器中运行完整PyTorch训练。PantryPilot实际是JavaScript项目，现有Python库存任务是重新编写的复现，不能作为“已导入真实PantryPilot仓库并修复”的证据。

## 实施顺序

先完成快照导入与固定测试，让真实目录能够在容器里稳定复现失败；再做多文件审批与补丁导出；随后补齐网页私有项目入口和证据展示；最后运行登记案例、部署复核并进行本人讲解验收。前一个环节未通过时不增加模型调用或界面装饰。
