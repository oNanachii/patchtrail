# Claude前端设计交接

本项目是PatchTrail，受控仓库排错与补丁验证工作台。后端核心在实现与独立验收中，当前`web/`为功能基线。请用户本人在Claude Code打开此项目；本交接不授权其他Agent代为启动、登录或发送任务到Claude。

## 设计目标

做一个适合真实开发者查看排错证据、审阅补丁和判断结果的完整前端。Claude可以自主决定视觉方向、字体、配色、布局及组件组织，优先让任务、当前阶段、证据和下一动作清楚。不要把API返回的工程信息全部堆成JSON墙。

首版可以保持HTML/CSS/JS，也可采用构建后输出静态文件的前端框架。后端仍由FastAPI提供同源API；构建产物要能由本项目部署。避免为了设计重写后端运行时。

## 必须保留的体验

- 任务列表及具体问题说明、执行方式选择和最近运行。
- 清楚区分脚本演示与真实DeepSeek，不把演示标为模型生成。
- 排队、调查、待确认、验证、成功、失败、取消和中断状态均有真实界面。
- 有选择地展示文件证据、工具结果、耗时与错误；完整报告仍可下载。
- diff审阅与确认绑定准确的`proposal_digest`和`expected_version`，不能仅按run_id审批。
- 模型自然语言回答不能呈现为验证成功，镜像/容器失败也不能呈现为业务失败已修复。
- 令牌仅留本页内存；创建结果不确定时保留同一幂等键和请求体，不能因再次点击或刷新重复新建付费作业。
- loading、空数据、服务失联、权限错误、版本冲突、缺容器、缺模型配置等路径真实可用。
- 桌面及390px窄屏、键盘操作和可读diff。不要添加假用户、虚构指标或占位按钮。

## API

以`patchtrail/api.py`和运行后的`/api/openapi.json`为准。状态响应中`checkpoint`已过滤内部模型消息；不要改变这一边界。匿名列表只显示公开demo，live详情、事件和报告需要操作令牌。

创建：`POST /api/runs`，JSON为`{task_id,mode}`，提供`Idempotency-Key`。mode为demo或live。确认：`POST /api/runs/{id}/approve`，JSON为`{proposal_digest,expected_version}`。另有取消与明确恢复接口。错误体统一为`{error:{code,message}}`，非2xx不代表fetch自动抛错。

## 验收与范围

先阅读AGENTS.md、PROJECT_STATUS.md与README，运行后端检查并记录真实结果。先改`web/`，接口确需调整时提出具体原因并与后端契约一起验证；不得绕过审批、鉴权、预算或容器边界。

提交设计说明、启动/构建命令、实际页面截图和浏览器流程结果。真实服务不可用时使用明确标记的设计fixture，不声称已经连通DeepSeek或容器。完成后交回Codex独立核对，再进行服务器切版和公开演示验收。
